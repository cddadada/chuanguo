# 60 秒回归检查清单

这份清单用于把原型从“看起来能用”变成“每次改完都能快速发现回归”。自动化优先跑 `npm run eval`，人工评审按本文件补充抽查。

## 自动检查

运行：

```bash
npm run eval
```

自动检查覆盖：

- `upload.html` 输入已知令号后，能从系统 mock 带出项目名称、锅筒图号、钢板数量和公司计划日期。
- 手工登记同一令号下多个锅筒后，状态写入同一份 `localStorage`。
- `printer.html` 对多锅筒令号默认展开到锅筒级打印项，不需要令号级二次点击。
- `checkin.html` 对数量工序录入的是新的累计数量，未达到目标数量时显示进行中。
- `dashboard.html` 能看到锅筒卡片、公司计划完工、打卡记录和计划调整入口。
- HTML 内联脚本可以被解析，不出现基础语法错误。
- 页面脚本中不残留旧口径：`撤回上次数量`、`不能小于当前已记录数量`、`卷制/纵缝`。

## 人工抽查

每次评审前抽查以下 8 项：

1. 打开 `index.html`，能在 1 分钟内讲清楚谁登记、谁打印、谁扫码、谁看板追踪。
2. 登记页新增令号和两个锅筒图号后，看板、打印页、扫码页都能读到同一份数据。
3. 打印页一个令号多个锅筒时，页面直接出现锅筒 1、锅筒 2 的打印项。
4. 扫码页没有“开始打卡”入口，只允许完成或撤回已完成工序。
5. 数量工序输入小于目标数量时，看板和扫码页都显示部分完成，而不是直接已完成。
6. 看板卡片不显示工序序号，只显示工序名称、计划完成和数量进度。
7. 打卡记录里保留完成和撤回流水，不直接删除历史记录。
8. README、PRD/SOP 和页面文案对“累计数量”“公司计划完工”“多锅筒打印”的说法一致。

## 回归高风险区

- `assets/state.js` 的 `PROCESS_NAMES`、`QUANTITY_PROCESSES`、`registerDrums`、`completeTask`、`revokeTask`。
- `upload.html` 的系统带出、数量工序目标数和重复登记提示。
- `printer.html` 的多锅筒默认展开。
- `checkin.html` 的数量录入、撤回和短暂防误点。
- `dashboard.html` 的筛选、记录抽屉、计划调整和权限入口。
