# Agent 运维说明

这份文档把 AI Builder 日报里的启发落到本项目：重点不是提示词，而是让 Codex 按稳定流程完成改动、验证和收口。

## 固定工作流

1. 读规则：先读本目录 `AGENTS.md`，再读上级 `prototypes/AGENTS.md`。
2. 定边界：确认本次改动属于页面、共享状态、文档、验证脚本中的哪一类。
3. 找上下文：跨页面逻辑先搜 `assets/state.js`，文档口径先搜 README 和 `docs/`。
4. 小步改动：优先增量修改，不重写整套原型。
5. 跑验证：改完执行 `npm run eval`；改脚本或核心逻辑执行 `npm run check`。
6. 报结果：最终回复必须说明改了什么、跑了什么验证、还有什么风险。

## 输入与输出

| 任务类型 | 输入 | 输出 |
| --- | --- | --- |
| 页面原型改动 | 业务口径、页面文件、共享状态 | HTML/CSS/JS 增量修改，附验证结果 |
| PRD/SOP 收口 | 评审意见、现有 README/docs | 文档口径统一，附旧口径扫查结果 |
| 评估脚本维护 | 回归风险点、页面结构 | `scripts/*` 可运行脚本，附通过/失败项 |
| 知识沉淀 | 已验证的稳定结论 | `AGENTS.md` 或 `docs/` 中的规则/清单 |

## 记忆边界

应该长期保留：

- 标准工序清单和业务对象粒度。
- 已确认的字段口径、权限口径和验收点。
- 验证命令和高风险回归点。
- 上线前必须转后端实现的能力边界。

不应该长期保留：

- 临时探索过程。
- 已废弃的页面文案。
- 一次性演示数据。
- 未经验证的外部链接和观点。

## 失败处理

- 自动测试失败：先读失败断言，再复现页面，不直接改断言。
- 页面无法打开：先确认是否是本地 `file://` 路径、资源路径或浏览器权限问题。
- 口径冲突：先以 `AGENTS.md` 和 README 的当前业务口径为准；需要调整时先改规则文档，再改页面。
- 新需求过大：先输出实施方案和影响范围，等 CD 确认后再动手。
